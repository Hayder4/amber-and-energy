# أمبر آند إنرجي — Amber & Energy

متجر إلكتروني متكامل لبيع الكهرمان الطبيعي والفاتوران الأصيل، مبني بـ Next.js 16 مع تصميم فاخر داكن/ذهبي، أنيميشن غني (Framer Motion)، دعم كامل للعربية (RTL) والإنجليزية، ولوحة تحكم إدارية كاملة.

## المزايا

- **واجهة متجر كاملة**: الرئيسية، المجموعات، صفحة المنتج (معرض صور، تفاصيل الكهرمان)، سلة تسوق، إتمام طلب، تسجيل دخول/خروج، حساب العميل وسجل الطلبات.
- **لوحة تحكم إدارية** (`/admin`): إضافة/تعديل/حذف المنتجات والمجموعات، إضافة خصومات (نسبة أو مبلغ ثابت، على منتج أو مجموعة أو الطلب كاملًا، بكود أو تلقائي)، إدارة حالة الطلبات، رفع صور المنتجات.
- **صلاحيات تلقائية**: أي حساب يسجّل بأحد البريد الإلكترونيات المذكورة في `ADMIN_EMAILS` (البريد الافتراضي: `amberandenergy@yahoo.com`) يحصل تلقائيًا على صلاحية **ADMIN** عند التسجيل أو تسجيل الدخول.
- **ثنائية اللغة**: عربي (افتراضي، RTL) وإنجليزي (LTR) مع مبدّل لغة فوري في الواجهة.
- **أنيميشن**: هيرو متحرك مع تأثير الباراﻻكس، كشف عناصر عند التمرير، أزرار مغناطيسية، عدّادات متحركة، مارّة نصية (marquee)، انتقالات صفحات سلسة، سلة منزلقة.
- **تجربة شراء كاملة**: كوبونات خصم، حساب الشحن (مجاني فوق حد معيّن)، الدفع عند الاستلام أو تحويل بنكي (بدون بوابة دفع فعلية).

## المتطلبات

- Node.js 20+
- npm

## البدء السريع

```bash
npm install
cp .env.example .env   # ثم عدّل القيم حسب الحاجة
npx prisma migrate dev # ينشئ قاعدة بيانات SQLite محليًا
npx prisma db seed     # يزرع مجموعات ومنتجات تجريبية بطابع "كهرمان أنتيك"
npm run dev
```

افتح http://localhost:3000

### الحصول على صلاحية المدير

سجّل حسابًا جديدًا من `/register` باستخدام أحد البريد الإلكترونيات المدرجة في متغيّر `ADMIN_EMAILS` (افتراضيًا `amberandenergy@yahoo.com`) — سيُمنح الحساب صلاحية **ADMIN** تلقائيًا وستظهر لوحة التحكم في القائمة العلوية بعد تسجيل الدخول.

## متغيرات البيئة (`.env`)

| المتغير | الوصف |
| --- | --- |
| `DATABASE_URL` | رابط اتصال قاعدة البيانات (افتراضيًا ملف SQLite محلي) |
| `AUTH_SECRET` | مفتاح سرّي لتوقيع جلسات تسجيل الدخول (JWT) — **غيّره قبل النشر** |
| `ADMIN_EMAILS` | بريد إلكتروني واحد أو أكثر (مفصولة بفواصل) تُمنح صلاحية المدير تلقائيًا |
| `NEXT_PUBLIC_SITE_NAME` | اسم المتجر المعروض |
| `NEXT_PUBLIC_CURRENCY` | رمز العملة (افتراضيًا `SAR`) |

## البيانات التجريبية

الصور الموجودة حاليًا في `public/images/` هي رسومات مولّدة برمجيًا (`scripts/generate-art.mjs`) بديلة عن صور حقيقية — لم يكن بالإمكان جلب محتوى الموقع القديم `amberandenergy.com` لأن الوصول إليه محجوب من بيئة التطوير هذه. استبدلها بصور حقيقية عبر لوحة التحكم (`/admin/products`, `/admin/collections`) في أي وقت — الرفع يخزَّن في `public/uploads`.

## قاعدة البيانات

المشروع يستخدم **Prisma 7** مع **SQLite** محليًا (`prisma/schema.prisma`، محرك `@prisma/adapter-better-sqlite3`). للانتقال إلى الإنتاج:

1. أنشئ قاعدة بيانات PostgreSQL (مثل Neon أو Supabase أو Prisma Postgres).
2. غيّر `provider` في `prisma/schema.prisma` من `sqlite` إلى `postgresql`.
3. ثبّت `@prisma/adapter-pg` بدلًا من `@prisma/adapter-better-sqlite3` وحدّث `src/lib/prisma.ts` وفق ذلك (راجع `.agents/skills/prisma-upgrade-v7/references/driver-adapters.md`).
4. حدّث `DATABASE_URL` في `.env` وشغّل `npx prisma migrate deploy`.

## أوامر مفيدة

```bash
npm run dev          # تشغيل بيئة التطوير
npm run build        # بناء نسخة الإنتاج (يشمل فحص TypeScript)
npm run start        # تشغيل نسخة الإنتاج
npm run lint         # فحص الكود
npx prisma studio    # واجهة رسومية لتصفح قاعدة البيانات
npx prisma db seed   # إعادة زرع البيانات التجريبية (يمسح البيانات الحالية)
node scripts/generate-art.mjs   # إعادة توليد صور الغلاف الاحتياطية
```

## هيكل المشروع

```
prisma/                  مخطط قاعدة البيانات + بذور البيانات
src/app/(site)/          صفحات المتجر (تستخدم شريط تنقل/فوتر المتجر)
src/app/admin/           لوحة التحكم (شريط جانبي منفصل)
src/app/api/             نقاط API (مصادقة، سلة، طلبات، إدارة)
src/components/          مكوّنات الواجهة (motion, shop, layout, admin)
src/lib/                 منطق مشترك: قاعدة البيانات، المصادقة، التسعير، الترجمة
src/proxy.ts             حماية مسارات /admin و /account (يعادل middleware سابقًا)
```

## ملاحظات أمنية قبل النشر الفعلي

- غيّر `AUTH_SECRET` إلى قيمة عشوائية طويلة (`openssl rand -base64 48`).
- انتقل إلى قاعدة بيانات حقيقية (وليس SQLite) عند النشر على منصّة بدون تخزين دائم مثل Vercel.
- الدفع حاليًا "عند الاستلام" أو "تحويل بنكي يدوي" فقط — لدمج بوابة دفع إلكتروني (مثل Moyasar أو Tap أو Stripe) يلزم تعديل `src/app/api/checkout/route.ts`.
